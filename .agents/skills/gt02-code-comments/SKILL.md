# GT02 中文函数与接口注释

## 适用范围与权限

- 面向本工程自己维护的 `.c`、`.h`，包括应用、服务、适配器、驱动、算法和测试。
- 所有新增函数、修改的函数均按本规范注释；用户要求为某个文件或模块补齐时，覆盖该范围内每个函数，包括静态函数、内联函数、线程入口、中断和宏定义形式的回调。
- 不因启用本技能就扫描改写整个工程。普通问答或评审只解释、报告；只有用户要求实现或补注释时才编辑文件。
- 不修改SDK、旧工程、第三方源码或 `build*` 生成文件来补注释，不改变接口、逻辑或配置来迎合注释。

## 语言与依据

- 说明文字使用中文；函数名、参数名、类型、宏、错误码和必要的协议/API名称保留原文。
- 注释解释“作用、目的、约定与限制”，不逐句翻译C语法，不用无意义的“初始化函数”“参数1”等描述。
- 先核对实现、调用者、配置和实际执行上下文，再写注释。SDK回调的参数语义需核对当前SDK声明及调用点，不能凭参数名猜测。
- 写当前实际行为，不把未来设计写成已有能力。不虚构空指针检查、超时上限、线程安全、错误码、自动重试或硬件保证。
- 注释与需求不一致时指出差异；仅补注释的任务不授权修复行为。不能确认的事实明确列为待核实，而不是写成接口保证。

## `.c`：每个函数前有简短说明

- 每个函数定义前写1～3句中文，说明做什么、为什么需要；有重要限制时再补一句。
- 有头文件契约的实现不用重复完整参数表；详细契约集中维护在头文件。
- 文件内静态函数没有头文件契约，除用途外，必要时简述特殊输入/返回值、状态副作用或调用上下文。
- 对线程入口、中断、定时器和解析回调，标明实际运行上下文及关键约束；不能笼统把所有回调都称为ISR。
- 复杂函数内部只对边界检查、状态转换、锁、缓存生命周期、异常处理和硬件时序等关键原因补注释，不强制每句代码都加注释。

示例，仅展示函数前简短说明的写法：

```c
/* 跨UART读取批次累积RX文本，遇到CR/LF后按完整行打印。
 * 仅由接收解析线程调用，不修改交给AT解析器的原始数据。
 */
static void log_rx_text(const uint8_t *bytes, size_t count)
```

## `.h`：详细说明使用契约

公共头文件和适配层私有头文件都适用。优先采用Doxygen形式，便于IDE悬停阅读；
仅需注释格式，不安装或引入Doxygen构建依赖。

### 文件与类型

- 文件开头用 `@file`、`@brief` 说明此头文件提供什么能力、供哪一层使用及重要边界。
- 对外结构体说明整体用途；每个成员说明含义、单位、有效范围，以及适用时的生命周期。
- 枚举逐项说明语义；位掩码说明能否组合；有语义的宏说明单位、上限及是否包含结束符。
- 函数指针/回调类型说明每个参数、返回值、调用上下文和数据有效期。
- 不给include guard等纯机械代码强加解释，不伪造作者、日期、版权或版本历史。

### 每个函数声明

使用 `@brief` 说明作用，并按真实情况补充以下内容：

| 项目 | 注释要求 |
|---|---|
| 每个具名参数 | 用 `@param[in]`、`@param[out]` 或 `@param[in,out]` 对应准确参数名；说明业务含义、单位及约束 |
| 指针与缓冲区 | 是否允许NULL、输入是否要求NUL结尾、容量与实际长度如何区分、单位是字节还是元素、是否含结束符 |
| 数据所有权 | 是否复制数据，调用后能否复用/释放，异步操作要求保留多久，由谁释放 |
| 返回值 | `@retval` 列举实际的重要成功值和错误值；剩余透传错误用 `@return` 说明来源，不漏写正数、句柄或枚举返回的语义 |
| 输出有效性 | 成功/失败时输出参数是否有效、清零、保持原值或部分写入；按实现描述 |
| 执行与并发 | 同步/异步，是否阻塞、等待什么、超时单位与特殊值、线程/ISR限制、可否并发及谁拥有可变状态 |
| 生命周期与副作用 | 初始化前提、能否重复调用、失败后能否重试，是否上电、停接收、清缓存或擦写持久数据 |

不适用的项不用堆砌。无参数函数不写假的 `@param void`；返回 `void` 的函数可写
`@return 无返回值。`，但仍需说明有意义的副作用或错误观察方式。
返回成功不等于异步操作完成：明确区分“启动/入队成功”“模组操作成功”和“平台应答成功”。

下面是虚构接口的格式示例，不是当前工程已有API或错误码保证；实际注释必须按源码改写：

```c
/**
 * @brief 将输入数据复制到调用者提供的缓冲区。
 *
 * @param[in] source 输入数据，不得为NULL；读取length字节。
 * @param[in] length 待复制字节数，允许为0。
 * @param[out] destination 输出缓冲区，不得为NULL；至少有capacity字节。
 * @param[in] capacity 输出缓冲区容量，单位为字节。
 * @retval 0 已复制length字节，不自动添加字符串结束符。
 * @retval -EINVAL 输入或输出指针为NULL，输出缓冲区不变。
 * @retval -ENOSPC capacity小于length，输出缓冲区不变。
 * @note 同步操作，不保留任何指针。输入与输出区域不得重叠。
 */
int example_copy(const void *source, size_t length,
                 void *destination, size_t capacity);
```

## 维护与交付检查

- 接口参数、返回值、阻塞/并发行为或数据所有权变化时，同步更新头文件注释与相关实现注释。
- 确认范围内的每个函数都有用途说明，头文件每个具名参数都被准确覆盖，枚举/成员说明不与代码冲突。
- 留意注释是否错误承诺线程安全、完整收包、零丢失、正常关机或可靠重试。
- 仅注释和skill文件变化时做格式、链接和一致性检查；代码也发生变化时按风险编译或测试。
- 交付时区分“规范已经建立”“哪些代码已补齐”“哪些仍未补齐”，不能把建立skill说成全工程已经加注释。
