# Lierda旧工程指令清单与接入

本次以旧工程`appcom/netmod/netmod_module_lierda.c`为指令来源，
结合`netmod_core.c`的ICCID解析规则，整理当前NT26-KCN适配器。
只补齐已有指令和基础查询，没有引入其他模组的命令，也没有复制旧网络任务。

代码入口：[命令标识和注释](../../adapters/modem/gt02_modem_lierda.h)、
[命令表和厂家回调](../../adapters/modem/gt02_modem_lierda.c)、
[厂家内部参数构造](../../adapters/modem/gt02_modem_lierda.h)、
[AT核心契约](../../adapters/modem/gt02_modem_at.h)。整体机制见[AT事务层第一版](12_AT事务层第一版.md)。

## 本次接入范围

旧文件包含20类命令，其中`CCLK`原先受`TIME_SERVICE_ENABLE`控制。
当前按命令类型登记21项：11项固定查询/握手、1项参数化LGPIO、9项标记`reserved = true`。
LGPIO原6个参数组合合并为1项，QTTSETUP原3组参数合并为1项；旧写法仍在本文记录。
原来28项中按参数值展开的ID已删除，不保留没有调用者的兼容别名。

```text
厂家提交(命令类型, 本次文本)
  ├─ 预留项 → 立即返回-ENOTSUP；不排队、不发送、不回调
  └─ 可执行项 → 独立复制请求 → FIFO → 原AT线程 → 收集正文 → 最终结果 → 厂家回调
```

增加固定大小的逐请求发送文本存储，没有增加服务层、线程或动态内存。原有AT、ATE0、CSQ的编号0/1/2保留。
原实板测试可顺序执行全部11条固定查询/握手，每条一次；默认现已切到[最小4G服务](15_4G最小服务与调用流程.md)，仅执行AT/ATE0准备和SIM查询。

## 可提交的11项

下表字符串不带CRLF；AT核心统一补齐。超时数值沿用旧命令表，单位毫秒。

| 命令ID（`LIERDA_CMD_`前缀省略） | 发送内容 | 超时 | 当前回调处理 |
|---|---|---:|---|
| AT | `AT` | 2000 | 握手结果 |
| ECHO_OFF | `ATE0` | 2000 | 关闭回显结果 |
| CSQ | `AT+CSQ` | 2000 | 检查RSSI/BER范围，最终OK后更新私有信号结果 |
| ATI | `ATI` | 2000 | 汇集厂商、型号、版本等多行原文并展示；不自动识别后端 |
| CPIN | `AT+CPIN?` | 2000 | 显示SIM状态，区分READY与其他状态；不自动解锁 |
| CGSN | `AT+CGSN` | 2000 | 检查1..19位数字并显示IMEI；不检查校验码 |
| CIMI | `AT+CIMI` | 2000 | 检查1..19位数字并显示IMSI |
| QCCID | `AT+QCCID` | 1000 | 允许20字符数字及大小写英文字母，保留原文，兼容外层双引号及空白 |
| CGREG | `AT+CGREG?` | 2000 | 按旧两字段格式`+CGREG: 0,stat`解析，1/5表示本地/漫游注册 |
| CCLK | `AT+CCLK?` | 2000 | 展示时钟原文，不解释时区、不设置系统时间 |
| QIACT_QUERY | `AT+QIACT?` | 10000 | 展示上下文原文，不激活PDP、不修改连接状态 |

IMEI/IMSI长度上限来自旧工程20字节缓存，保留一字节给结束符；这不是对所有模组标识长度的通用承诺。
CGREG仍限定旧格式中的模式0和状态0..5；附加位置字段等扩展回复会报告未支持，不静默丢弃字段。
ICCID长度暂沿用旧`NETMOD_ICCID_DIGITS = 20`；按用户确认放宽为`0..9`、`A..Z`、`a..z`，不是仅允许十六进制字母。
保留原始大小写，不删除或替换字母。空值、内嵌NUL、控制字符及标点仍不作为有效标识接受。

`QIACT?`允许仅返回OK，此时日志说明“没有返回上下文行”。有正文时仅展示原文，
没有做IPv4/IPv6、上下文编号或激活状态的业务解析。其余数据查询要求至少有正文，单独OK不够。
ATI、CCLK同样只是原文查询，不宣称已完成型号校验或时钟同步。

新增结果目前在AT线程内解析/打印，没有新增跨线程状态查询接口。
信号私有缓存也不供其他线程直接访问；后续服务需要结果时，再接入有明确所有权的事件或快照。

## 参数化LGPIO：一个类型，不枚举所有参数组合

命令表只保存`LIERDA_CMD_LGPIO`，`command="AT+LGPIO"`、`parameterized=true`、超时2000 ms。
原有表项仍保持一条命令占一行。厂家内部入口：

```c
/* 仅在厂家流程或明确的bring-up测试中使用，不暴露给公共服务。 */
gt02_lierda_gpio_config(97);     /* AT+LGPIO=97,1 */
gt02_lierda_gpio_set(99, false); /* AT+LGPIO=99,1,0 */
```

当前只接受旧工程实际使用的97/99，电平取0/1，不推断实际音频电路极性。
这些函数先检查参数，再用snprintf构造完整命令并检查截断，最后调用`gt02_at_submit_text`。
固定模式1沿用旧代码，不对其他模组或其他GPIO作兼容承诺；未自动调用这些函数。
最终OK/ERROR由注册的LGPIO回调报告，不等于TTS播放完成。

```text
厂家有类型的参数 → 构造完整文本 → submit_text(ID, text)
                                     ↓
                             复制到4个队列槽位之一
                                     ↓ 出队时再次复制
                              独立在途文本存储
                                     ↓
                              回调完成后可复用
```

每份文本上限128字节，另加NUL；核心统一追加CRLF。成功提交后，调用者可以立即改写或释放构造缓存。
同一个ID可连续提交不同文本；没有每次改写静态表或其user_data，ID不表示请求编号。
回显过滤使用本次完整命令，正文仍共享原512字节响应缓存。

submit_text只允许参数化项，且文本须以表项命令名紧跟等号开头，等号后至少一个字符。
空文本、错误模式/命令名、控制字符/非ASCII返回-EINVAL；超过128字节返回-EMSGSIZE；队列满返回-ENOBUFS。
所有拒绝均不回调、不发送。厂家仍须检查参数语义及引号等转义，AT层不会替厂家解析参数。
普通submit不能发送参数化表项，避免把不完整的`AT+LGPIO`误发给模组。

## 待接入的9类

下表字符串记录旧写法；厂家表仅为参数化类型保存命令名，不再保存printf模板。
对reserved项，submit和submit_text都返回`-ENOTSUP`，不能借参数化入口绕过限制。

| 命令ID（前缀省略） | 旧写法 | 超时 | 尚缺的处理 |
|---|---|---:|---|
| RESET | `AT+RESET` | 2000 | 协调AT核心停止/恢复与模组重新启动的生命周期 |
| QICSGP | `AT+QICSGP=1,1,"%s","%s","%s",%d` | 5000 | APN、用户、密码及认证方式的参数化和长度检查 |
| QIDEACT | `AT+QIDEACT=1` | 2000 | 上下文释放及已有连接清理 |
| QIACT | `AT+QIACT=1` | 10000 | 激活流程与最终网络状态判断 |
| QIOPEN | `AT+QIOPEN=1,%hhu,"TCP","%s",%hu,0,1` | 4000 | 参数化、连接编号、异步`+QIOPEN`完成结果 |
| QICLOSE | `AT+QICLOSE=%hhu,10` | 2000 | 按连接编号关闭及状态/缓存清理 |
| QISEND | `AT+QISEND=%hhu,%hu` | 10000 | 提示符、定长二进制发送、SEND OK/FAIL |
| QTTS | `AT+QTTS=1,"%s"` | 2000 | 旧UTF-16十六进制编码、长度和播放完成事件 |
| QTTSETUP | `AT+QTTSETUP=1,1,0`、`1,2,32767`、`1,3,0` | 2000 | 厂家TTS流程中的参数构造与调用顺序 |

旧文件使用的APN认证方式包括0/1/2；本版没有实现认证策略。
音频参数仅按旧代码命名，不凭参数编号猜测音量、音调等具体含义。
`QIOPEN`的4000 ms是旧命令表里的等待值，不是整条TCP连接的可靠总超时。
收到AT的OK、PDP激活和TCP连接成功是三个不同结果，后续实现不能混为一谈。

## 正文分发的一个小扩展

保留`response_prefix`和`require_response`，补充空字符串的明确含义：

| `response_prefix` | 行为 |
|---|---|
| `NULL` | 不收集正文，例如AT、ATE0 |
| `"+CSQ:"`等非空前缀 | 只收集匹配的正文，原有规则不变 |
| `""`空字符串 | 先排除最终结果、回显和已注册URC，再收集其他正文；供ATI/IMEI/IMSI使用 |

已注册的RDY即使夹在ATI两行正文之间，也只进入URC回调。
未注册的异步消息仍可能混入空前缀正文，因此数字查询还会检查完整格式；ATI只展示原文。
这不等于自动识别所有URC，也不支持二进制数据模式。
正文仍共用一个512字节缓存，多行以换行分隔；失败和超时不会交付半截正文。

旧URC的接入状态：

| 旧监听规则 | 本版处理 |
|---|---|
| RDY | 保留即时回调 |
| `+CCLK:`（条件功能） | 只在CCLK查询中作为正文，不另注册同前缀URC；未接时间服务 |
| `+QIOPEN` | 待连接状态机接入，当前仅可能看到原始行日志 |
| `+QTTS: 0` | 待TTS功能接入，当前不发布播放完成事件 |
| `+QIURC:` | 待TCP接入；尤其recv后的定长二进制不能交给当前文本行解析器 |

不应在此版本直接让模组主动发送TCP载荷来验证接收；文本核心还没有定长二进制模式。

## 如何验证新增查询

在AT核心初始化、模组上电并就绪后，调用既有接口，例如：

```c
/* 在测试控制线程中提交一条SIM查询；返回0只表示入队。 */
int ret = gt02_at_submit(LIERDA_CMD_CPIN);
```

结果从厂家回调日志观察。按一条一条的方式验收，或在完成回调中非阻塞提交下一条，
不要一次提交全部11项：核心仍只有4个待执行位置。
切换到原全量查询测试模式后会执行全部11条，无需逐个修改请求；默认最小服务只执行AT/ATE0准备和SIM查询。
原厂家表保持只读，测试副本只包装查询最终回调：先解析/打印，再唤醒控制线程提交下一条。
测试期间仍注册完整厂家配置，不删除LGPIO或其他预留项；但启动流程不执行它们。

实际顺序为AT、ATE0、ATI、CPIN、CGSN、CIMI、QCCID、CSQ、CGREG、CCLK、QIACT查询。
明确ERROR记失败后继续，例如模组不支持CCLK时仍尝试QIACT查询；超时或AT流失步时停止，避免将迟到响应错配。
控制线程另有15秒回调等待保护，到期只停止，不取消请求或自动恢复。
最终计数只表示AT事务结果：正文格式是否有效、SIM是否READY、是否注册及是否有上下文，须结合厂家日志判断。
