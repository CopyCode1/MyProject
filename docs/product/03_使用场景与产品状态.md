# GT02 使用场景与产品状态基线

> 当前行为来源：`gt02new_newui_app.c`  
> 目标：保留产品语义，重新设计为可测试的Zephyr事件状态机

## 1. 旧系统启动顺序

旧工程大致按以下顺序启动：

```text
时钟/FPU/看门狗/复位原因
  → 系统Flash锁和基础设施
  → Counter32k
  → AppReg配置
  → BLE
  → Publicparam
  → Powermng
  → Resourcemanager
  → LED/Key
  → IMU
  → ACMD
  → Netmod
  → GNSS
  → UWB（当前硬件分支已注册）
  → Remotetrans
  → Application
  → OPEN全部组件
  → 每20 ms轮询全部组件
```

新工程不复制“每20 ms轮询全部组件”，但要保持必要的初始化依赖，例如配置存储必须在读取产品参数前可用。

## 2. 产品主状态

旧应用定义了以下运行状态：

| 状态 | 产品语义 | 主要行为 |
|---|---|---|
| `NONE` | 尚未确定状态 | 完成启动后选择OFF、SELFTEST或NORMAL |
| `OFF` | 软件关机/待开机 | 保持最小功能，响应充电或按键开机 |
| `SELFTEST` | 自检 | 检查LED、按键、语音、IMU、SIM、网络、GNSS和UWB |
| `NORMAL` | 正常运行 | 保持基础连接和产品交互 |
| `POSITION` | 周期定位 | 开启定位相关能力并形成上报数据 |
| `SLEEP` | 静止休眠 | 降低功能，只保持必要连接 |
| `DEEPSLEEP` | 深度休眠 | 停止更多服务，等待唤醒或周期定位 |
| `ONESHOT_POSITION` | 单次定位 | 在休眠期间临时完成若干次定位确认 |
| `SHUTDOWN` | 关机过渡 | 停止远程服务、保存状态并进入OFF |

新状态机应修正拼写，但需要维护旧状态到新状态的明确映射。

## 3. 核心状态转换

```text
BOOT/NONE
 ├─ 已保存关机状态 ─────────────→ OFF
 ├─ 非NORMAL运行模式 ───────────→ SELFTEST
 └─ 正常配置 ──────────────────→ NORMAL

NORMAL/POSITION
 ├─ 到达定位周期 ───────────────→ POSITION
 ├─ 持续静止达到阈值 ───────────→ SLEEP
 ├─ 收到关机请求 ───────────────→ SHUTDOWN
 └─ 充电或检测到移动 ───────────→ NORMAL

SLEEP
 ├─ 继续静止达到深睡阈值 ───────→ DEEPSLEEP
 ├─ 到达休眠定位周期 ───────────→ ONESHOT_POSITION
 ├─ 充电、移动或SOS ────────────→ NORMAL/POSITION
 └─ 收到关机请求 ───────────────→ SHUTDOWN

DEEPSLEEP
 ├─ 到达休眠定位周期 ───────────→ ONESHOT_POSITION
 ├─ 充电、移动或SOS ────────────→ NORMAL/POSITION
 └─ 收到关机请求 ───────────────→ SHUTDOWN

SHUTDOWN ───────────────────────→ OFF
```

当前默认连续定位配置：定位周期1000 ms、静止75 s进入休眠、3600 s进入深度休眠、休眠260 s执行一次定位、静止60 s触发报警。运行设备的持久化配置可能覆盖这些默认值。

## 4. 产品场景

### SCN-001 正常上电

前置条件：设备处于允许开机状态，电池电压有效。

流程：

1. 获取并记录复位原因；
2. 初始化最低限度平台服务；
3. 读取设备身份和持久化配置；
4. 初始化用户交互和必要设备；
5. 根据运行模式进入NORMAL或SELFTEST；
6. 启动定位、联网和远程服务；
7. 通过LED/马达/可选语音提供启动反馈。

异常：配置损坏时使用受控默认值并记录；非关键外设失败不能阻止日志和诊断启动。

### SCN-002 关机状态下充电

旧行为：检测到充电时显示电量；达到配置条件时可以自动开机；充电场景还可能进入Terminal/发卡器交互。

待验证：自动开机的真实电量门槛、充电完成灯效以及工装交互时序。

### SCN-003 按键开机和关机

旧行为：

- OFF状态下长按触发开机反馈；
- 正常状态下超长按进入关机确认；
- 确认或超时后执行相应动作；
- 特殊长按组合可能进入BLE UART模式。

新实现必须把按键识别与产品动作分开：key driver只产生动作事件，产品状态机决定开关机或模式切换。

### SCN-004 周期定位和上报

流程：

1. 定位周期到达；
2. location service请求GNSS及已启用的其他定位源；
3. 收集GNSS、IMU、BLE和UWB信息；
4. 计算定位质量；
5. 通过XRP或JT808编码；
6. network service通过4G发送；
7. 记录成功、失败和重试结果；
8. 返回NORMAL、SLEEP或DEEPSLEEP策略。

### SCN-005 静止、休眠与唤醒

旧行为：充电或IMU检测到移动时不进入休眠；持续静止后依次进入SLEEP和DEEPSLEEP；休眠期间仍可周期单次定位。

新实现需明确每个状态中BLE、4G、GNSS、UWB和IMU的电源策略，避免各模块独立决定整机睡眠。

### SCN-006 SOS报警

触发源：SOS按键动作。

外部行为：

- 设置远程SOS状态；
- 设置UWB SOS标志；
- 退出静止/休眠计时；
- 使用红灯、马达和语音提示；
- 在后续远程报文中携带SOS；
- 支持清除或服务端处理。

### SCN-007 静止、跌倒和超速报警

- 静止：IMU持续冻结超过阈值后触发，移动后清除；
- 跌倒：读取IMU跌倒标志，设置远程事件并清除一次性标志；
- 超速：GNSS速度超过阈值并持续指定时间后报警，使用回差防抖。

报警规则属于domain层，IMU和GNSS驱动只提供测量和设备事件。

### SCN-008 4G联网与远程消息

流程：模组上电、ATI识别、SIM检测、网络注册、TCP连接、协议登录/心跳、定位上报及下行处理。

下行能力包括文字、语音播放、配置或控制、时间、AGNSS数据和OTA事件。每一种下行消息都必须有长度校验和明确所有者。

### SCN-009 自检

旧自检涉及：

- 多色LED；
- 按键单击/双击/超长按；
- 语音；
- 充电状态；
- IMU移动；
- SIM卡；
- 4G网络连接；
- GNSS定位；
- 可选UWB测距。

新工程把自检作为独立application mode，复用正式驱动和服务，不建立第二套硬件驱动。

### SCN-010 OTA

旧产品存在Terminal YMODEM和远程网络升级路径。新工程统一为：

```text
BLE / UART(YMODEM或MCUmgr) / 4G
              ↓
         ota transport
              ↓
       image writer/validator
              ↓
            MCUboot
```

传输中断、写入中断、校验失败、新镜像启动失败和回滚都必须形成测试场景。

## 5. 新架构事件草案

| 事件 | 生产者 | 消费者 |
|---|---|---|
| `APP_EVT_BOOT_COMPLETE` | platform | product state machine |
| `APP_EVT_KEY_ACTION` | key input | product/UI/alarm policy |
| `APP_EVT_CHARGE_CHANGED` | power service | product/UI policy |
| `APP_EVT_BATTERY_CHANGED` | power service | product/UI/reporting |
| `APP_EVT_MOTION_CHANGED` | IMU service | product/power policy |
| `APP_EVT_FALL_DETECTED` | IMU service | alarm domain |
| `APP_EVT_POSITION_READY` | location service | remote/reporting service |
| `APP_EVT_MODEM_STATE` | modem service | network/product diagnostics |
| `APP_EVT_REMOTE_COMMAND` | remote service | command dispatcher |
| `APP_EVT_OTA_STATE` | OTA service | product/UI policy |
| `APP_EVT_SHUTDOWN_REQUEST` | key/power/remote | product state machine |

事件名称和载荷会在对应功能设计时确定；当前表只用于划分所有权。

## 6. M0待验证行为

- 实际出货设备开机默认进入NORMAL还是首次进入SELFTEST；
- 每种按键动作的准确时间阈值；
- 开机、关机、定位、联网和充电的完整LED时序；
- UWB在V412/V202A设备上的默认启用方式；
- SIM错误是否始终语音提示后关机；
- 屏幕是否参与当前产品交互；
- Terminal与GNSS的资源切换条件；
- 各状态真实功耗和外设上/下电状态。
