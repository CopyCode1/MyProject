# 4G统一能力接口与操作表

当前状态（2026-11-04）：已重新实现[驻网与数据就绪检测](16_4G驻网与数据就绪检测.md)，默认通过本接口组织一次启动和周期查询；旧最小服务的历史说明仍保留。

原`interfaces/gt02_modem_hw.h`已改名并扩展为
[gt02_modem.h](../../interfaces/gt02_modem.h)，不保留重复的接口头文件。
原电源和字节I/O类型、符号及实现保持原样，协议能力集中在同一文件定义。

## 三组表的使用者

| 操作表 | 注入对象 | 当前实现 |
|---|---|---|
| `gt02_modem_power_ops` | 生命周期调用者/检测服务 | `gt02_modem_zephyr_power`：init、power_on、power_off |
| `gt02_at_io_ops` | AT事务核心 | `gt02_modem_zephyr_io`：read、write |
| `gt02_modem_ops` | 检测服务或独占验证入口 | `gt02_lierda_ops`：init、prepare、query |

统一头文件只定义契约，不创建线程、不转发函数、不绑定具体GPIO或AT命令。
具体厂家由装配层选择，服务只保存公共操作表指针，不需要`LIERDA_CMD_*`。

## 首版协议能力

- `init(callback, user_data)`：绑定一次事件回调，不上电、不初始化AT、不发送命令。回调不得为NULL，上下文覆盖整个开机生命周期，不能重新绑定。
- `prepare()`：异步完成AT后ATE0。调用者先完成硬件上电及当前板/模组需要的启动等待；此方法不等待RDY、注册或PDP。
- `query(GT02_MODEM_QUERY_SIM)`：异步查询SIM；`GT02_MODEM_QUERY_SIGNAL`返回原始CSQ RSSI；`GT02_MODEM_QUERY_LTE_REGISTRATION`返回LTE/EPS注册状态。
- `query(GT02_MODEM_QUERY_DATA_CONTEXT)`：返回产品数据上下文，当前Lierda固定选择CID 1、IPv4；不配置APN或执行激活。复用原有QIACT查询命令ID，不增加操作表函数。

prepare/query返回0表示已接受，之后只产生一次对应完成事件；返回负值表示未接受，没有完成事件。
同一时刻只接受一个协议操作，其他请求返回-EBUSY。回调可能很快发生，不能等函数返回后才准备接收上下文。
若AT尚未初始化，提交失败会撤销操作占用，不阻止调用者在完成初始化后再次请求。

## 启动通知与完成事件

`gt02_modem_event`按值描述结果，不携带原始AT响应指针：

| 字段 | 有效条件 |
|---|---|
| type | STARTUP_READY、PREPARE_DONE或QUERY_DONE，必须先检查 |
| query | 只在QUERY_DONE时使用，表示SIM、信号、LTE注册或数据上下文查询 |
| error | 0表示协议操作及所需正文解析成功；负值为失败 |
| sim | 仅SIM查询成功时有效，其他情况为UNKNOWN |
| signal_rssi | 仅信号查询成功时有效，取值0..31或99（未知）；业务阈值由后续调用者决定 |
| registration | 仅LTE注册查询成功时有效；1为本地注册，5为漫游注册 |
| data_context | 仅数据上下文查询成功时有效，含active及4字节IPv4；其他情况为全0 |

当前SIM正文映射READY、SIM PIN、SIM PUK、NOT READY，分别交付就绪、需要PIN、需要PUK、未就绪。
这些状态均可属于一次成功查询；不执行解锁，也不能据此承诺网络或TCP就绪。
不支持或无法解析的正文返回-EBADMSG；AT超时映射-ETIMEDOUT；其他AT失败暂映射-EIO，不能区分全部模组拒绝/底层失步原因。
正文后收到ERROR时不会交付正文中的READY，失败数据统一为UNKNOWN。

事件由AT线程回调，指针仅在回调内有效。上层需要跨线程处理时复制整个结构，不能保留指针。
回调内不得阻塞等待AT，可非阻塞投递消息；队列满须有明确的错误收尾路径。
操作完成通知前释放内部占用和短锁；启动通知只在锁外回调，不清除进行中的操作。
Lierda每次RDY独立产生STARTUP_READY，由服务按当前阶段过滤重复；必须在供电前注册回调。
检测服务把事件按值入队，由服务线程组织流程；启动通知本身不代表注册或TCP可用。

## 当前装配及检查顺序

```text
准备硬件控制脚
    → gt02_at_init：绑定厂家profile和字节I/O，启动唯一RX线程
    → service_start内调用gt02_lierda_ops.init：注册结果出口
    → power_on：先UART后供电
    → 等待STARTUP_READY（上电期间早到事件保留，超时则停止，不发AT）
    → modem_ops.prepare：AT/ATE0
    → 收到PREPARE_DONE且error=0
    → modem_ops.query(SIM) → 读取SIM结果
    → modem_ops.query(SIGNAL) → 读取原始信号结果
    → modem_ops.query(LTE_REGISTRATION) → 读取LTE注册结果
    → modem_ops.query(DATA_CONTEXT) → 读取目标上下文和IPv4
    → 发布本轮结论，按结果等待下一轮
```

公共表由[gt02_modem_lierda.h](../../adapters/modem/gt02_modem_lierda.h)导出，
实现函数在[gt02_modem_lierda.c](../../adapters/modem/gt02_modem_lierda.c)内保持static。
LGPIO等厂家内部辅助能力仍在私有边界内，不加入公共服务接口。

## 数据上下文的结果含义

`gt02_modem_data_context`的`active`只描述模组报告的激活状态，不承诺IP可用。没有CID 1行或只有OK是成功的inactive结果；其他CID不会被误选。
厂家层先校验目标行、地址语法和完整性，最终OK后才发布；目标重复、嵌入NUL、越界IPv4或尾随垃圾返回错误，失败载荷清零。IPv6目标返回-ENOTSUP。
`0.0.0.0`可被解析但不允许服务放行。检测服务还排除首字节为0、127或大于等于224的地址，不根据未知子网掩码臆测广播地址。
查询成功、上下文激活、数据就绪和TCP连接成功是不同结果。具体服务判定及有效期见[周期检测说明](16_4G驻网与数据就绪检测.md)。

## 与现有验证代码的关系

旧[最小4G服务](15_4G最小服务与调用流程.md)已删除，其流程及测试结果仅作历史参考。当前默认运行新的[周期检测服务](16_4G驻网与数据就绪检测.md)，原信息查询入口作为互斥模式保留。
原始AT验证没有公共操作在执行时只保留日志，不会制造无请求的公共完成事件。
协议操作表与旧bring-up不得同时驱动同一模组，尤其不能混用相同AT命令，否则没有请求编号来区分归属。

厂家源码随`CONFIG_GT02_MODEM_AT`构建，不依赖服务或临时测试开关；当前应用在服务或独立AT信息查询模式下初始化AT，两种控制者通过Kconfig互斥。
不在当前阶段增加空的TCP、APN或TTS函数指针。
AT超时先回调-ETIMEDOUT并隔离旧回复，期间提交返回-EAGAIN且不产生事件；旧结束行及残留输入处理完后可重新提交。
传输/解析故障封闭提交入口，返回-EPIPE；服务通过独立注入的会话恢复能力组织一次重启，不能通过重新init绕过失步。
具体故障通知、隔离期限及恢复前提见[AT超时隔离与会话恢复](17_AT超时隔离与会话恢复.md)。

```powershell
west build --no-sysbuild -b qemu_cortex_m3 -d ../_verification/MyProject/modem_capability tests/modem_at -- -DCONFIG_AT_TEST_CAPABILITY=y
west build -d ../_verification/MyProject/modem_capability -t run
```

仿真通过不等于新增公共能力已在实板验证；本轮不自动烧录。
