# GT02 行为等价与验收计划

> 目标：证明Zephyr新实现逐项达到`gt02_4g`的产品能力，而不是仅证明代码能够编译

## 1. 验收原则

1. 每个功能先在旧设备采集基线，再验证Zephyr实现。
2. 测试记录必须包含固件版本、硬件版本、配置和测试环境。
3. 正常路径、超时、断开、掉电和恢复都属于功能的一部分。
4. 如果新行为有意优于旧行为，需要记录为架构决策，不能无声改变协议或交互。
5. 不在日志、抓包附件或文档中提交真实密码、密钥和生产凭据。

## 4. 单个功能完成标准

任何功能从`IMPLEMENTED`升级到`VERIFIED`前，必须满足：

- 需求ID、状态、输入输出和边界明确；
- 正常行为通过；
- 关键超时和故障通过；
- 日志足够定位问题且不泄露敏感信息；
- 相关单元、组件或板上测试通过；
- Flash、RAM、线程栈和功耗影响有记录；
- 与旧产品的差异已记录；
- 设计文档、DTS、Kconfig和测试记录保持一致。

## 5. 首轮旧设备采集清单

在开始复杂功能前，对旧设备执行并保存以下事实：

1. 上电、正常启动、关机和充电启动的视频及日志；
2. SOS按键单击、双击、长按和超长按的灯光/马达/语音结果；
3. 4G模组`ATI`结果，敏感标识需要脱敏；
4. GNSS启动信息、样本NMEA和首次定位时间；
5. 一次正常定位上报抓包，服务器地址和凭据需要脱敏；
6. BLE广播包、服务UUID及一次完整命令交互；
7. ACTIVE、SLEEP和DEEPSLEEP电流；
8. 当前设备中保存的关键参数与代码默认值差异。
