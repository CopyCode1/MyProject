# GT02 硬件资源基线

> 基线：`gt02_4g` + `PRODUCT_GT02NEW` + `HARDWARE_VERSION_V412_V202A`  
> 数据来源：旧工程板级头文件和当前目标源文件  
> 原则：首版Zephyr定义保持相同芯片和连接，但仍需用原理图/实板复核

## 1. 板型身份

| 项目 | 当前基线 |
|---|---|
| SoC | Nordic nRF52840，`NRF52840_XXAA` |
| CPU | Arm Cortex-M4F |
| 旧无线栈 | S140 SoftDevice |
| 新无线栈 | Zephyr Bluetooth Host/Controller |
| 产品宏 | `PRODUCT_GT02NEW` |
| 硬件选择器 | `GT02_HARDWARE_VERSION_SELECTOR = 1` |
| 硬件宏 | `HARDWARE_VERSION_V412_V202A` |
| 旧代码版本 | `SOFTWARE_MAJOR=18`、`SOFTWARE_MINOR=9` |

注意：SES属性中存在`arm_target_device_name="nRF52832_xxAA"`，但编译宏、启动文件和向量表均指向nRF52840。新工程以nRF52840为准，不复制这个旧工程配置矛盾。

## 2. 引脚编号解释

旧工程中：

```c
#define P0_PIN_NUM 32
```

因此`P0_PIN_NUM + n`表示nRF52840的`P1.n`，不是`P0.n`。本文已转换为明确的端口形式。

## 4. 总线资源

### 4.1 IMU I2C

| 项目 | 值 |
|---|---|
| 旧实例号 | TWI 1 |
| SCL | P0.14 |
| SDA | P0.19 |
| INT1 | 未连接，`0xff` |
| INT2 | 未连接，`0xff` |
| 设备 | LSM6DSO |
| I2C地址 | 0x6A |
| WHO_AM_I | 0x6C |

首版优先评估Zephyr现有ST LSM6DSO驱动是否覆盖FIFO、步数、跌倒和旧算法所需采样模式；不够的能力放在专用扩展驱动中。

### 4.2 4G UART

| 项目 | 值 |
|---|---|
| MCU RX | P0.07 |
| MCU TX | P0.27 |
| Zephyr预留实例 | UART1，当前DTS保持disabled；UART0继续用于日志 |
| 波特率 | 旧 `netmod_port_lte.c` 配置115200，无奇偶校验 |
| RTS/CTS | 未定义 |
| 电源 | P0.31 |
| PWRKEY | P1.08 |
| 支持模组 | Air780系列、Lierda/NT26系列 |
| 实际贴装型号 | VERIFY_HW：读取模组标签或旧固件ATI响应 |

旧软件在启动后通过`ATI`自动识别`AirM2M`或`Lierda`。即使当前PCB只贴一种模组，新架构仍应把两种实现限制在modem adapter内。

当前DTS仅描述连接关系：`modem0`别名指向自定义 `gt02-modem-interface` 节点，
其 `uart` 属性引用UART1，`power-gpios` 为P0.31高有效，`pwrkey-gpios` 为P1.08高有效。
没有为控制脚设置自动输出，也没有启用任何具体模组驱动。UART1暂不初始化，
待确认实物型号、上电时序及IO电平后再接入串口/AT适配器。详见 [4G硬件接口](08_4G模组硬件接口.md)。

### 4.3 GNSS UART

| 项目 | 值 |
|---|---|
| MCU RX | P1.09 |
| MCU TX | P0.11 |
| 波特率 | 115200 |
| RTS/CTS | 未连接 |
| 电源 | P0.08 |
| WAKE | 未连接，`0xff` |
| 旧代码可识别厂商 | BK1660、UM220、CM262、P20M |
| 实际贴装型号 | VERIFY_HW：读取芯片/模组标签或启动输出 |

旧代码声明“GNSS UART与Terminal复用”。当前引脚不同，实际复用的是UART控制器/软件资源而不一定是物理引脚。Zephyr设计前必须确认两者是否能同时工作。

### 4.6 外部NOR SPI

| 项目 | 值 |
|---|---|
| 旧实例号 | SPI 2 |
| SCK | P0.04 |
| MISO | P0.28 |
| MOSI | P0.25 |
| CS | P0.26 |
| 外部Flash型号 | Winbond W25Q128JV，用户已确认 |
| 当前NCS接入 | SPIM2，8 MHz，Zephyr `jedec,spi-nor` 官方驱动 |
| 当前`gt02_4g`实际使用 | VERIFY：SES源列表包含内部Flash资源管理，未见该外部Flash端口被加入当前目标 |

本轮在用户确认型号后启用外部Flash节点，接线沿用本表旧工程定义，待实板验证。启动仅查询ID、容量并读取首尾各32字节，不调用擦除或写入，不分配产品分区。旧端口接受 `EF 40 18` 与 `EF 70 18` 两种JEDEC ID，NCS实现保持一致；详细步骤见 [外部Flash接入验证](06_外部Flash接入与只读验证.md)。

| 信号 | 引脚 |

| CS | P1.12 |
| SDA | P0.02 |
| SCL | P1.14 |

当前目标编译宏不是`GUI_ENABLE`，因此屏幕是否属于出货功能标记为`VERIFY`。在实机确认之前，不应让屏幕阻塞M1。

## 6. DTS设计原则

首版自定义板应表达：

- 四路LED和SOS按键aliases；
- 电机、外电检测和电源控制GPIO；
- SAADC电池通道；
- LSM6DSO I2C节点；
- 4G、GNSS和Terminal的UART pinctrl；
- DW1000 SPI节点及控制GPIO；
- 经验证后再启用外部NOR和屏幕节点；
- 后续MCUboot所需Flash分区。

禁止把上述引脚复制到业务C文件。业务只使用语义化设备接口。

## 7. 原理图/实板复核清单

- 4G实际型号和UART波特率；
- GNSS实际型号；
- LSM6DSO地址选择脚；
- DW1000 IRQ触发沿、RESET电气类型和WAKE时序；
- 电池分压比例和AIN3输入范围；
- 外部电源检测上下拉；
- LED和马达驱动极性；
- 32.768 kHz与高频晶振配置；
- NFC脚是否被当作GPIO使用；
- 外部NOR是否实际贴装和使用；
- 屏幕是否实际贴装和属于当前产品功能；
- GNSS与Terminal的UART实例复用限制。
